# PhoneXR v0.11 — Scene Anchors

Бесплатный экспериментальный браузерный VR-пасстру для телефона в обычных VR-очках.

**Запуск:** https://astsrotcreator.github.io/phonexr/?v=11

## Что есть

- Видео задней камеры в двух половинах экрана (одна и та же камера, **не стерео**).
- Плавающие окна, заметки, таймер, часы, счётчик и настройки.
- Управление указательным пальцем и щипком через MediaPipe.
- Счётчики FPS камеры, FPS интерфейса и частоты распознавания руки («ИИ/с»).
- **AR по камере (2D):** окна привязываются к исходным деталям изображения через `vision-anchor-v11.js`. Когда камера теряет именно эти детали, окна скрываются, а не приклеиваются к другой поверхности. Когда исходная поверхность снова опознана, окна могут появиться в прежнем месте на экране.
- **AR по датчикам (3DoF):** экспериментальная фиксация по направлению. На Redmi 13 ненадёжна, так как аппаратного гироскопа нет.
- Режимы проверки камеры и производительности без отслеживания рук.

## Как тестировать на Redmi 13

1. Открыть ссылку в Chrome по HTTPS; обновить страницу.
2. Для проверки базовой плавности отключить «AR по камере», «AR по датчикам» и «Тест скорости без распознавания руки» включить. Запустить PhoneXR и записать **кам** и **UI** FPS.
3. Для теста камерного AR включить «AR по камере», а тест без распознавания руки пока оставить включённым. Навести заднюю камеру на контрастные детали (картина, книжная полка, текстура стены), **убрать руку из кадра**, затем нажать в VR «⟳ ПРИВЯЗАТЬ».
4. Медленно поворачивать телефон, **сидя и глядя на экран без очков**. Смотреть статус «слежение», процент качества и количество точек. При повороте камеры в другую сторону исходные ориентиры исчезают, поэтому **окно должно скрыться из поля зрения**. Если снова направить камеру на исходные детали, алгоритм попытается повторно их распознать. Однотонная стена и быстрый разворот приводят к потере ориентиров, иногда требуется снова нажать «ПРИВЯЗАТЬ».
5. Только затем можно включить распознавание руки и проверить щипок. Для облегчения нагрузки отключить «Показывать точки руки», снизить «Качество распознавания руки» до 160–224 px.
6. Если AR работает плохо, снять галочку «AR по камере» — обычное видео и окна продолжат работать.

## Ограничения и безопасность

**Нельзя ходить по дому, лестницам, улицам или рядом с препятствиями, ориентируясь только через эти VR-очки.** Камера моноскопическая и запаздывает, нет надёжной стереоглубины, определения препятствий или пространственного позиционирования.

Этот проект **не реализует 6DoF, SLAM, ARCore, распознавание глубины, карту комнаты или отслеживание физического положения**. Камерный AR компенсирует лишь простое 2D-смещение видимых деталей, может ошибочно потерять или сопоставить детали и не гарантирует, что окна останутся на одном физическом месте. При головной боли, тошноте, усталости сразу прекратите использование.

Официальный FAQ Xiaomi подтверждает отсутствие гироскопа у Redmi 13: https://www.mi.com/global/support/faq/details/KA-206710/

WebXR для полноценного AR на Android требует совместимости с ARCore: https://developers.google.com/ar/develop/webxr/requirements

## Файлы

- `index.html` — интерфейс PhoneXR
- `hand-worker.js` — MediaPipe Hand Landmarker в отдельном потоке
- `vision-anchor-v11.js` — фиксация на исходной сцене, скрытие вне кадра, поиск при возвращении
- `vision-anchor-worker.js` — старый экспериментальный движок v0.10 (не используется новой версией)
- `camera-test.html` — проверка разрешения камеры

GitHub Pages: Settings → Pages → Deploy from a branch → main / (root).
